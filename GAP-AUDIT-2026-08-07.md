### The three findings worth carrying forward

**1. G41 changed a number that had already been reported.** The 2026-08-03 briefing stated
`+$261.77` of residual "market move". Corrected, that run's real market performance was
**−$1,021.52** — a $1,283 swing and a sign flip. Cash deployment had been narrated as performance.
Any conclusion drawn from that day's attribution should be re-read with this in mind.

**2. G44's earlier write-up was itself wrong, and the correction is the lesson.** It had been
recorded as a "likely misread TTM/annualized figure — a data error." It was not:

- smith-quality's arithmetic was **correct and exactly reproducible** — `413.9/50.8 = 8.15x`, then
  `350.1/256.1 = 1.37x`. Its 8.1x → 1.4x was right.
- The $256.1M was **real money** — pretax income fell to $83.3M from $381.6M while operating income
  barely moved, so ~$267M of below-the-line expense genuinely landed.
- What it actually was: MRVL closed **Celestial AI + XConn** that quarter (+$2.8B goodwill, +$1.0B
  intangibles) alongside a $1.0B 5.300% 2036 notes issue. At 5.3% on $1B, incremental run-rate
  interest is ~$13M/quarter — nowhere near $200M. The 10-Q's own interest expense line is **$52.8M**
  (+8.4% YoY), i.e. ~6.6x coverage. Healthy.
- So the failure was **interpretation, not calculation**: a one-time acquisition-financing charge
  that yfinance buckets under "Interest Expense" was read as a permanent change in cost of debt —
  and the strategist's MRVL veto and trim rested on it.

Prevention is now in `smith-quality.md`: a >2x single-quarter coverage move is a data question
before a credit finding. Also documented there — **`get_financials` silently ignores
`period="quarterly"` and returns ANNUAL columns**; the honoured parameter is `frequency`. Nothing in
the response indicates which basis you got.

## Re-validated as genuinely unfixable (1)

**G18 — SPY/QQQ max-pain.** Re-tested rather than taken on trust: sampled SPY across four
expiries — three near-dated weeklies **and** a 43-DTE standard monthly, since monthlies are where
real OI normally sits. Open interest is **uniformly 0** on every call and put at every expiry (bid
and ask are zero too; only Last, Volume and IV are populated). Max-pain is OI-weighted, so it stays
uncomputable from this feed. Barchart *does* carry OI (see G57) but publishes aggregate totals, not
the per-strike OI max-pain needs. `wont_fix` is correct.

**FMP evaluated and ruled out** (follow-up question, same day). The connector exposes 28 tools and
none is an options endpoint — verified against the endpoint enums of the two likeliest, `quote` and
`directory`. `commitmentOfTraders` does carry "open interest", but for CFTC **futures** positioning,
not equity option strikes; it is not a substitute. This tier is also already demonstrably limited
(`etfAndMutualFunds` blocked per G19, per-symbol earnings blocked per G20).

Full source matrix for options data in this stack:

| Source | Per-strike OI (max-pain) | Aggregate OI (PCR) |
|---|---|---|
| FMP connector | ✗ no options endpoint | ✗ |
| yfinance | ✗ zero on every strike/expiry | ✗ |
| Barchart put/call-ratios | ✗ totals only | ✓ **works — live PCR source** |
| Barchart options chain | ✗ JS-rendered, WebFetch sees the template | — |

So the split is cleaner than it appeared: **PCR is fully solved** and needs no further work.
**Max-pain alone stays blocked**, because it is the single computation requiring the per-strike
distribution — precisely the part no reachable source renders. Closing it needs a new data source
(paid options feed, or CBOE/OCC delayed data): a scope decision, not a defect.

## Opened, then self-corrected and closed (1)

**G57 — PCR provenance.** This audit raised G57 claiming smith-macro's "SPY PCR 1.88 (OI)" was
impossible, since yfinance returns zero open interest on every strike. **That claim was wrong, and
the reasoning error is worth keeping.** It assumed yfinance was the source. It isn't — smith-macro's
own TOOLS line and task 2 both name **Barchart** as the primary PCR source, with yfinance only as a
fallback. Barchart publishes genuine OI; verified by fetching it: SPY put OI 13,911,974 vs call OI
6,065,745 (ratio 2.29), volume ratio 1.24. The 08-03 figure was legitimate.

The lesson: an audit that infers a source instead of checking it manufactures false findings. Two
real defects did survive the false alarm, and both are now fixed in `smith-macro.md`:

1. **Provenance** — the output never said which source each figure came from, which is exactly why a
   *correct* number couldn't be defended when questioned. The agent now emits
   `spy_pcr_oi_source` / `spy_pcr_vol_source` (+ QQQ) and states the source inline. An untraceable
   number gets treated as suspect, which is worse than a labelled approximate one.
2. **The fallback is not equivalent and would fail silently** — yfinance OI is 0 on *every* strike
   and *every* expiry (re-verified across near-dated weeklies **and** a 43-DTE standard monthly;
   bid/ask are also 0). So an OI-based PCR there computes as 0/0, and a single-expiry volume PCR
   isn't comparable to Barchart's whole-chain figure (~1.97M SPY put volume vs one skewed slice).
   The agent must now emit `null` rather than a zero or a mislabelled volume figure, and must not
   trend a fallback number against prior Barchart runs.

This also confirms **why G18 stays `wont_fix`**: max-pain needs *per-strike* OI, and the only
OI-bearing source in this stack publishes aggregate totals only.
