## Orchestration

**Skill**: `/Users/yb/.claude/skills/agent-smith/SKILL.md` — the orchestrator. Runs
QUICK (default, 3-agent roster) or DEEP (adds book/scout/macro plus conditional
agents). Compute-first: all deterministic arithmetic goes through
`scripts/smith_math.py`, never through an LLM sub-agent re-deriving a number the
script already owns.

Flow (stable step numbers are cited elsewhere, so SKILL.md's own numbering is the
source of truth for order — this is a summary): LOCK → intraday-refresher check
(→ an optional PRICED REFRESH branch that reruns the compute pipeline and
strategist only, on live prices, without a full Stage-1 dispatch) → MEMORY load
(state.json + `freshness`/`validate`/`runs`/`learn-lessons` self-checks) → market
inputs (one batched fetch, shared with The Operator via a cross-skill cache) →
holiday/session check → dashboard-decision sync (drains any Accept/Reject/Hold
clicks the published dashboard collected since the last run) → PREFETCH + TICKER
RESOLUTION + COMPUTE (one holdings snapshot, `smith_math.py pipeline` runs every
compute stage, `slices` renders each agent's data embed) → **STAGE 1 in dependency
waves** (Wave 0 script-only ledger/lots facts → Wave 1 observers in parallel → tails
merged and Wave 2 re-sliced off them → Wave 2 interpreters in parallel → a
`crosscheck` pass over both waves' verdicts) → **STAGE 2** (`smith-strategist`,
Wave 3, consuming verdicts that have already seen each other) → SYNTHESIZE (briefing
+ dated report) → dashboard rebuild/publish → PERSIST (state/ledger/proposals,
atomic writes) → `compact` (archive, never delete) → release lock.

The wave rewrite (2026-09-06) exists because flat-parallel dispatch let sibling
agents form contradictory verdicts with no way to see each other's evidence —
full incident history in DECISIONS.md.

## Compute layer

`scripts/smith_math.py` remains the single CLI entry point (`python3
scripts/smith_math.py <subcommand>`), but the implementation was split
2026-08-16 across several modules once `smith_math.py` alone passed 4,000 lines
mixing unrelated domains:

- `smith_core.py` — shared constants, `load_json`/`emit`/`fail`/`clamp`.
- `smith_risk.py` — risk primitives and the canonical readers for mixed-shape
  fields (thesis status/text/evidence, gap status) — see ONE FIELD, ONE READER
  in SKILL.md's hard rules.
- `smith_ledger.py` — FIFO lot reconstruction, corporate actions, the
  email-confirmation parser (`ledger-parse`/`ledger-apply`), `bookcalc`/`taxcalc`.
- `smith_memory.py` — retention/`compact`, archives, `gaps` (BM25 precedent
  search), `validate`, `slices` (per-agent data-embed rendering).
- `smith_lifecycle.py` — proposal lifecycle: `add-proposal`, `score`, `stops`,
  `dismiss`, condition-based auto-retirement.
- `smith_conviction.py` — the conviction/sizing engine the non-ATR proposal
  triggers (oversold_reversion, catalyst_threat, cluster_rotation, etc.) size
  through.
- `smith_learning.py` — the self-learning substrate (`learn-status`,
  `learn-lessons`, priority-parameter escalation).
- `smith_dashboard.py` / `smith_charts.py` — generate `dashboard.html` (payload +
  client-rendered app; v1's ~35 hand-wired HTML builders were replaced 2026-09-09).
- `smith_math.py` itself — the per-run compute stages (`book`, `risk`, `drift`,
  `journal`, `attribution`, `rotation`, `sentiment`, `derisk`, `triggers`,
  `buckets`, `ladder`, `build-holdings`, `pipeline`) plus the whole CLI dispatch
  table (40+ subcommands as of this writing — run `smith_math.py --help` for the
  current list rather than trusting a count written down here).

Two modules sit outside the split as their own standalone CLIs, not registered
into `smith_math.py`'s subcommand dict:
- `smith_valuation.py` — reverse-DCF, ROIC-vs-WACC, Beneish/Altman forensic
  scores (its one per-run compute stage, `valuation`, IS registered).
- `smith_edgar.py` — SEC EDGAR primary-source verification (as-filed XBRL
  figures) and Form 4 insider-cluster detection.

Sub-agents receive the script's output inline (via `slices`, never a pointer to a
whole state file) and reason from it — an agent that estimates a number instead of
reading it from the script or a tool is a defect, not a shortcut.

## Sub-agent fleet

| Agent | Dispatch | Scope |
|---|---|---|
| `smith-signals` | every run (Wave 1) | Judges pre-computed setup buckets (`smith_math.py buckets` owns the arithmetic — RSI/ATR/peer-relative math is not this agent's job), news/insider/swing signals, journal judgment |
| `smith-thesis` | every run (Wave 2) | Per-holding thesis (intact/strengthening/watch/broken) with mandatory `evidence_for`/`evidence_against`, factor-overlap read, sector map. Consumes Wave 1's catalyst/signals/quality tails before writing a verdict |
| `smith-watchlist` | every run (Wave 1) | Entry setups, earnings-calendar cache, attribution-driven scan (attribution math precomputed) |
| `smith-book` | deep only (Wave 2) | Narrative only — dividends, ex-dates, LTCG lot narrative, beta-cache refresh. Weights/concentration/drawdown/cash come from `compute_book.json` |
| `smith-scout` | deep only (Wave 1) | Pre-market/international-session narrative, sentiment read, diversifier-bench maintenance |
| `smith-macro` | deep only, PLUS quick when `\|us10y_change_pts\| ≥ 0.12` or `vix ≥ 22` (added 2026-09-14) | Fed/FOMC stance (cached to the meeting cycle), options PCR/max-pain (precomputed by `smith_math.py maxpain`), FOMC/CPI/NFP calendar, regime read |
| `smith-catalyst` | event-triggered, any mode: gate=ESCALATING, SMH ≥3%, any Asia index ≥3%, any cluster ≥4%, deep run, or the user asks why something moved (Wave 1) | Named/dated/sourced factor catalysts with a magnitude ratio against the affected holding; non-destructive merge (a quiet-day empty return carries prior catalysts forward rather than wiping them) |
| `smith-quality` | monthly (2nd deep review of the calendar month) or on-demand "quality check" (Wave 1) | Credit-officer's lens (PAT-vs-OCF, dilution, leverage, going-concern) plus Beneish M-Score/Altman Z-Score/reverse-DCF via the orchestrator's own FMP/EDGAR calls |
| `smith-cycle` | monthly (1st deep review of the month) or on-demand (Wave 2) | Single AI-capex cycle_position (accelerating/mid/late/rolling) with a stated falsifier, from hyperscaler capex guidance + memory pricing + semicap book-to-bill |
| `smith-earnings` | deep run with a held name reporting within 5 trading days, or a narrow VERIFY-ONLY pass any mode when `validate` finds a stuck-PENDING earnings_facts entry (Wave 1) | Owns "beat"/"miss" for the fleet, option-implied expected move vs actual, tags unverified press-release figures until `smith_edgar.py` confirms via SEC XBRL |
| `smith-tax` | deep run with open trims, or on demand (Wave 2) | Which LOTS a trim sells, LTCG-boundary proximity, harvesting candidates — unblocked 2026-08-15 once lots.json became engine-built/reconciled |
| `smith-cluster` | deep only, up to 3 per run, round-robin-selected by `smith_math.py ladder` (Wave 2) | The one comparative question no other agent owns: within a cluster sharing one tailwind, which member captures the most of it. Reads `rel_intra_pp`/dispersion from `compute_ladder.json`; judges cross-member read-throughs and a bench of non-held names |
| `smith-rebound` | any run when `compute_triggers.json.correction_state` is `correction`/`deep_correction` — never the pre-market gate, stop-outs, or spare cash | Finds names fallen too far in a broad correction (biased toward high-volatility names) as relief-rally candidates, sized off actual support levels |
| `smith-ledger` | exception-only — dispatched by the orchestrator's own script-first pipeline (`ledger-parse` → `ledger-apply` → `lots`) ONLY when a row is unresolvable or a reconciliation fails | Owns the confirmation-email pipeline's hard cases; routine parsing is plain regex + arithmetic reconciliation, no LLM call |
| `smith-strategist` | every run (Wave 3 / Stage 2) | Sized proposals (never executed), stress table (deep), risk-off check, hit-rate readout — consumes the Stage-1 tails plus precomputed `compute_triggers`/`compute_drift`/`compute_risk`, never recomputes them |

Dispatch discipline: every prompt embeds slices only (holdings rows, `compute_*.json`
refs, prior JSON tail, trimmed known_gaps) — never a pointer to a whole state file an
agent must re-read. Tail validation on every return; malformed JSON gets one
re-emit retry before falling back to a degraded, flagged section.

## State model

`/Users/yb/Claude/AgentSmith/` is the memory of record (git-snapshotted after every
run, pushed to a private `agent-smith-state` GitHub repo). Working rule:
**state.json is working memory, not an archive** — a declarative `RETENTION` table
drives `smith_math.py compact` (dry-run by default, `--write` to apply, run after
every deep persist), which archives closed gaps beyond the 8 most recent,
thesis/sector_map entries for names no longer held, and terminal proposals past the
90-day scoring window — **archive, never delete**, and every evicted record stays
queryable via `smith_math.py gaps`. Current archive files: `known-gaps-archive.json`,
`exited-holdings-archive.json`, `proposals-archive.json`, `journal-archive.json`
(created on first eligible eviction).

**Freshness is tracked per artefact**, not assumed: `smith_math.py freshness` ages
every declared data cache and sub-agent output against its own TTL and prints a
`fresh|stale|dark|unstamped|missing` state plus a one-line headline that goes in
every briefing header. This is what catches a factor-catalyst snapshot or a thesis
map going quietly stale while live prices keep moving around it.

## Decision and accountability layer

Two of the four "known gaps" in the previous version of this file are now built,
not open:

- **Decision queue**: the published dashboard (`smith_dashboard.py`, v2 rebuilt
  2026-09-09) carries Accept/Reject/Hold buttons on proposals plus eight other
  surfaces (watchlist/diversifier suppression, de-risk overrides, gap resolution,
  learning-parameter approval, thesis confirm/override, catalyst "priced in"). A
  click republishes the page with the decision embedded in a JSON blob; the next
  orchestrator run drains and applies it (`sync-decisions`) before anything else,
  so a decision is durable within one run's latency, not instant. Every open
  proposal also carries a computed `priority` (HIGH/MEDIUM/LOW) from typed trigger
  data — never parsed rationale prose — so repeated restatement of the same idea is
  visible instead of silently re-listed as new.
- **Benchmark-relative accountability**: `benchmark_price_at_proposal` (added
  2026-09-07) lets `smith_math.py score` grade a BUY/TRIM/SELL against SMH's own
  move rather than the stock's raw move, when the anchor is present. Coverage is
  still building forward from that date — proposals written before it fall back to
  absolute-move grading, flagged in `scorecard.data_quality` rather than silently
  mixed in.

An explicit investment mandate now exists (`INVESTMENT-POLICY-STATEMENT.md` — 2-5yr
horizon, 25% total-book drawdown ceiling, a two-regime cash band that separates
"cash is high because stops fired" from "cash is high because we aren't deploying",
and a prose-only glide-path for years 3-5 not yet wired into policy.json — see that
file's own section 2 for why it's deliberately deferred, not forgotten).

## Known architectural gaps (still open)

- **No event-driven wake.** The daily cron (and an on-demand deep/quality-check
  ask) remain the only triggers. A drawdown-rung crossing or a gap-risk event
  intraday gets no response until the next scheduled run or a user-initiated
  refresh/priced-refresh. Nothing currently watches the book between runs.
- **IPS glide-path automation.** The year 3→5 de-risk schedule (raise cash floor,
  step the AI-capex ceiling down) is specified in prose in the IPS but not yet a
  dated trigger in policy.json — correctly deferred while the mandate is still in
  its first year, but it needs to actually get built before year 3 arrives.
- **Proposal dedup can drop a `pair_id` link on a same-day, same-ticker,
  same-direction merge** (found live 2026-09-14, in progress — see DECISIONS.md
  and the spawned fix task) — the dedup key correctly collapses restated ideas but
  doesn't yet preserve which rotation pair a surviving row belonged to when two
  independent pairs propose the same buy leg on the same day.
- **This file itself will drift again.** Nothing enforces that ARCHITECTURE.md gets
  touched when the sub-agent roster or dispatch conditions change — it was caught
  stale by an external review, not by any internal check. Treat "does
  ARCHITECTURE.md still match SKILL.md's actual dispatch table" as worth
  re-verifying occasionally rather than assuming it holds.
