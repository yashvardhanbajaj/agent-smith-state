### 7. PERSIST (before the milestone block)
WRITE SAFETY (state.json, journal.json, proposals.json — the files whose loss can't be reconstructed): before overwriting, copy the current file to `<name>.bak` (one generation is enough); then write the new content to `<name>.tmp` and `mv` it over the original — an interrupted run leaves either the old file intact or a stray .tmp, never a truncated memory-of-record. If on any run state.json fails to parse at MEMORY load, fall back to state.json.bak (say so) before resorting to the legacy milestone-JSON path.

- **quality_financials (added 2026-09-01)** — whenever `smith-quality` ran, merge its returned `financials_updates` (per ticker) into `state.data_cache.quality_financials` non-destructively — only the tickers it actually fetched fresh this pass; every other ticker's cached entry is left untouched (`smith_memory._merge_quality` does this via `merge-tails`, same shape as `quality_flags`' own per-ticker merge). This is the raw-figures cache smith-quality's own task 0 checks before calling `get_financials` again — distinct from `quality_read` (verdicts), which was the only thing cached here before this date.
- thesis / earnings_facts (the persist-layer half of G58 — the serialization half lives in the EVIDENCE PRINCIPLE above) — merge smith-thesis's `thesis.changed` into `state.thesis` **as objects, preserving `evidence_for`, `evidence_against`, `verified`, `verified_against` and `verified_on` on every entry.** Do NOT flatten an entry back to a bare one-liner string to save space. If a sub-agent returns a legacy bare string for a name, keep it but set `verified: "unverified"` and add a data_quality line naming it. Merge any returned `earnings_facts` into `state.data_cache.earnings_facts` (append/overwrite per ticker; a durable verified-fact store, entries persist until the next reported quarter supersedes them). Assert every changed thesis entry has BOTH evidence arrays present before writing — a missing key is a schema violation, note it in data_quality and set `verified: "unverified"` rather than silently accepting it.
- **factor_catalysts / factor_themes (full incident: DECISIONS.md#G50 — `smith_dashboard.py` reads `state.factor_catalysts` directly, and this key sat undocumented-as-a-write-target for a week while smith-catalyst's fresh output was discarded every run, so the panel served stale events as current).** Whenever `smith-catalyst` ran this sweep: **REPLACE** `state.factor_catalysts` with the catalysts it returned (never append — it's a point-in-time snapshot of what's moving the factor now, not an accumulating log), keeping each catalyst's `magnitude` field (a threat stored without its scale is the "5 units vs ASML's 131" failure this agent exists to prevent); merge `theme_updates` into `state.factor_themes.themes[]` (match on theme `id`, add the new `live_<date>` key — this IS the accumulating long-horizon record). **If smith-catalyst did NOT run this run, leave the existing array untouched** — a stale-but-labelled catalyst is recoverable, an erased one is not.
- signal_history / signal_history_as_of (full incident: DECISIONS.md#G62) — **whenever `smith-signals` returns successfully, stamp `state.signal_history_as_of[ticker] = today` for EVERY ticker it scanned**, alongside the usual bucket write; nothing else may write that stamp, and it must *freeze* (not backfill) when signals fails, since that is what makes it an exact staleness measure. `cmd_rotation` stops treating a NEW HEADWINDS bucket as a veto once its stamp is older than `HEADWIND_BUCKET_MAX_AGE_DAYS` (10) or missing entirely; the bucket is still reported as context. Never stamp a ticker signals didn't actually cover — a stale bucket silently vetoing a live trigger is exactly the failure this stamp exists to catch.
- ledger.csv — append via `python3 scripts/smith_math.py append-ledger --base-dir . --ts <ts> --mode <mode> --value-usd <> --usdinr <> --wallet-usd <> --spx <> --ndx <> --value-trust ok --summary "<short one-liner, max 300 chars>" --briefing-file runs/<ts>/briefing.md` — **this is the only sanctioned way to write a ledger row (added 2026-08-29, full story: DECISIONS.md#G84).** `--summary` is a skimmable one-liner; the full run narrative goes in `--briefing-file` (write it to `runs/<ts>/briefing.md` BEFORE calling this command), and the CSV cell stores only a pointer to it. This split exists because a ~4,000-character prose blob typed directly into the notes cell is exactly the medium a fact drifts in — a nonexistent "8% drawdown warn line" propagated across four consecutive rows before anyone checked it against policy.json. `--summary` over 300 chars is refused outright, and validate's `validate_policy_narrative_drift` checks the latest row's numbers against policy.json. Skip entirely on weekend/holiday/refresher runs.
- journal.json — merge compute_journal.json's journal_updates (scores/verdicts) and any signals-agent journal_new entries; store the updated bucket_hit_rates and name_bucket_grades. PRUNE: move fully-scored entries >12 months to journal-archive.json, keeping aggregate counts.
- proposals.json — apply strategist's new proposals via `python3 scripts/smith_math.py add-proposal --base-dir . --proposals-json <specs.json> --run-dir runs/<ts> --today <date>` — **this is the only sanctioned way to append new proposals (added 2026-08-29, full story: DECISIONS.md#G84).** It builds `action` FROM `ticker`+`direction` (e.g. `{"direction":"SELL","ticker":"ASML",...}` → `action:"Sell ASML"`), so the label can't be a bare direction word by construction — never hand-write a proposal dict with `action` set directly. **Extra spec fields are NOT ignored (corrected 2026-09-20 — the old "silently ignored" wording documented a bug as a feature: `stop_price_usd` survived on 9 of 323 rows and `evidence_quality` was last stored 2026-08-25, which left the G58 evidence gate and two retirement branches unreachable).** A typed `PASSTHROUGH` allowlist is validated and stored on the row: `stop_price_usd`, `stop_distance_pct`, `target_price_usd`, `size_wanted_usd`, `clamped_by`, `risk_usd`, `r_multiple`, `ev_r`, `p_win`, `horizon_days`, `expires_on`, `invalidation`, `evidence_quality` (a `{verified,computed,unverified}` count dict), `trigger_bucket`, `exited_on`, `conviction_score`, `gate`. A `null` value means "not supplied" and is skipped. A mistyped passthrough value, or any spec naming a lifecycle-owned `RESERVED` field (`id`, `status`, `date`, `created_utc`, `outcome_*`, `priority*`, `history`, `repeat_count`, `superseded_by`, `retired_*`, `dismissed_by`), **rejects the whole batch and writes nothing** — fix the spec and re-run. Any other unknown field is kept under the row's `spec_extras` and named in the result's `data_quality`, never lost. Do not try to hand-merge duplicates here; that's `proposals`' job, next. **DO NOT hand-filter the strategist's tail before this call** (corrected 2026-09-10, a real mistake made the same day it's dated) — `add-proposal` already accepts `size_usd: 0` with no special case, and the `proposals` dedup pass below is specifically built to merge duplicates by (ticker, direction) regardless of size. Excluding a $0-clamped leg "to be safe" adds a manual judgement call that buys no safety and can silently drop a genuinely new (if currently unfunded) idea from the record. Pass the strategist's proposals through with only trivial field renaming; the only proposals that should be withheld are ones the STRATEGIST ITSELF flagged as not yet proposable (e.g. "no live price this run, not sizing on a stale anchor") — that is the strategist's judgement surfacing, not a filter the orchestrator should be applying on top of it. Then run `python3 scripts/smith_math.py proposals --run-dir runs/<ts> --today <date>` (part of the DASHBOARD ARTIFACT pipeline, §6) — this collapses any open proposal that shares a (ticker, direction) with another currently-open one into a single row, keyed off direction buckets BUY/TRIM/SELL/HOLD (not raw verbs — "Light trim X" and "Trim X" are the same direction), regardless of how many calendar days apart they were made (full incident: DECISIONS.md#G87 — the dedup key used to include the date, so the same idea restated on a different day was never recognized as a duplicate; 32 open → 19 on first run once fixed). The survivor keeps the chronologically latest date/size/rationale, the older occurrence(s) fold into a `history[]` array, and `repeat_count` tracks how many times the idea has been reiterated. Every proposal also gets a stable `id` (`P-###`, assigned once, never reused) so it can be referenced precisely later. **Dismissing a proposal**: when the user says "dismiss P-014" (or similar), run `python3 scripts/smith_math.py dismiss --base-dir . --id P-014 --reason "<why, if given>"` — sets `status: "dismissed_by_user"`, a terminal status the dedup pass never reopens or re-merges. **This same mutation is also reachable via the dashboard's Reject button** (§1.7) — both paths call the identical `dismiss_proposal_core` in `smith_lifecycle.py`. A button click can't write proposals.json in real time (no capability lets a published page write to this Mac's filesystem — checked against the real artifact-capabilities contract), but it durably holds the decision by republishing itself, and §1.7's sync step reconciles it on the next run — a click is not instant, but it is not cosmetic either. Score past (non-open) proposals at 30d/90d with outcome_pct + verdict (open|worked|missed) — a merged proposal's `history` entries are the same underlying idea and count once toward the scorecard, not once per historical restatement. Compute per-proposal and aggregate strategist scorecard.
- **New proposal fields (added 2026-08-25, interactive dashboard)** — `accepted_by_user` status (button-recorded intent to act, deliberately distinct from a ledger-confirmed `executed`/`fulfilled`/`filled`) with `accepted_on`/`accepted_reason`; `held_on` (a list of dates) / `held_reason` for a proposal the user tapped Hold on without dismissing; `revived_by_user_on` when an auto-retired proposal is reopened via the dashboard's Revive button. None of these are written by hand — all three come out of `sync-decisions` (§1.7), never edited directly.
- **New state.json keys (added 2026-08-25, same feature)**: `watchlist_suppressed` (`{"TICKER":{"date","reason"}}`, shared by the watchlist and diversifier-bench "Not interested" buttons — read by `cmd_triggers`' `entry_setup`/`bench_diversifier` generators via `smith_risk.is_watchlist_suppressed`, so a suppressed name simply stops being re-proposed rather than being deleted from any history), `derisk_overrides` (`{"TICKER":{"date","reason"}}`, the de-risk queue's "disagree" button — read by the dashboard render, NEVER by `cmd_derisk`'s scoring itself, since a real risk signal is only ever annotated, not suppressed), `catalyst_suppressed` (`[{"headline","date","suppressed_on","reason"}]`, the factor-catalysts "already priced in" button — smith-catalyst's dispatch prompt should be told the current suppressed list so it doesn't re-surface the same story). All three follow the same shape convention on purpose (a dict or list of small dated records) so a future fourth suppression list doesn't need a fifth ad-hoc schema.

**Condition-based auto-retirement, priority scoring, honest sizing and rotation pairs → `reference/proposals-engine.md`.** The `proposals` subcommand re-tests every open proposal against **today's** structural conditions each run and retires the ones whose trigger has objectively cleared (`status: "auto_retired"` + `retired_reason`); it tags each open one `priority: HIGH|MEDIUM|LOW` with a numeric `priority_score` and `priority_reasons[]`, entirely from typed data the pipeline already has — **it never parses rationale prose**, which is exactly what made an earlier voider false-positive. Current weights, the four retirement conditions, the `full_cure_usd`/`tranche_note` honest-sizing fields, the `stretch`/`signal_conviction` dimensions, `bucket_hit_rates_7d`, and rotation-pair (`pair_id`/`pair_role`) construction all live in that reference file with the incident each was built against.

Two rules that stay here because they are easy to break by accident:
- **A proposal with no live trigger of any kind is capped at MEDIUM**, however high its stacked score runs. Cap/cluster/cash/repeat stacking describes the portfolio's composition, not a reason the stock should move.
- **Judgement calls are never auto-actioned.** A proposal whose price has drifted ≥10% since it was written gets a `review_flags` entry and stays open. `auto_retired` is distinct from `superseded` and from `dismissed_by_user`, so the audit trail shows who retired what.

- trigger_journal.json — append `compute_triggers.json`'s `shadow_new` array (the `laggard_rotation` / `profit_ratchet` / `scale_out_ladder` candidates, each with `price_at_flag` and `scored: false`). Same shadow-scoring contract as `derisk_journal.json` (§2.9c): score entries at 7d and 30d against `price_at_flag`, and only once a trigger has a real hit rate should promoting it from shadow to live be considered. **Do NOT append the live triggers** (`oversold_reversion`, `overbought_distribution`) — those are already tracked as real proposals in proposals.json with full lifecycle management, and journaling them here would double-count them in any future hit-rate readout.
- **lots / corporate actions — `smith_math.py lots`.** `python3 scripts/smith_math.py lots --base-dir . --holdings runs/<ts>/holdings.json` rebuilds lots.json from trades.json by deterministic FIFO and reconciles every lot sum against broker quantities. **Dry run by default; `--write` to apply.** It **refuses to clamp** — a sell consuming more than exists is reported as a `phantom_short` with its date, never floored at zero, which is how G71's GOOG short stayed invisible for weeks. Corporate-action rows live in trades.json (`ca_type` ∈ conversion/split/fractional_credit/spinoff/adjustment; `source` required — an unsourced row is unverifiable, and a `conversion` carries cost basis AND acquisition date, so the LTCG clock does not restart). **Cutover status and full rationale → `reference/proposals-engine.md`.**
- **proposal scoring — `smith_math.py score`. Run on EVERY deep review, before the briefing.** `score --base-dir . --prices-json <p.json> --today <date>` — probe once with a file containing `{}` and it NAMES the tickers it needs (they include EXITED names, so this is its own fetch, not a reuse of holdings quotes). **Include SMH in that fetch** — BUY/TRIM/SELL proposals carrying a `benchmark_price_at_proposal` (added 2026-09-07, see smith-strategist.md) grade as alpha vs SMH rather than the stock's raw move, but only if SMH's current price is in the same prices-json; without it those rows silently fall back to absolute-move grading, flagged in `scorecard.data_quality`. Grades every closed proposal at 30d/90d, direction-aware, writes `outcome_pct`/`outcome_verdict` and an aggregate `scorecard`. It quarantines rather than grades any row whose implied move (stock OR benchmark) exceeds ±35% — a corrupt anchor once set the entire trim-accuracy figure on n=7. **Why it is not optional → `reference/proposals-engine.md`:** the desk graded its indicators for a month while grading none of its decisions.
- policy.json — write strategist's draft on bootstrap ("confirmed": false). User-confirmed edits set "confirmed": true. Never modify a confirmed policy without explicit instruction.
- lots.json — script-owned: rebuilt from trades.json by `lots`; never hand-edited.
- trades.json — script-owned: fills via `ledger-apply`, reasons via `trade-rationale`; never hand-edited.
- known_gaps — add a new entry (next sequential ID) the first time a data-quality issue is found; do NOT re-add if the ID already exists — agents/strategist just cite it. Remove (or mark resolved) a gap once its underlying cause is fixed (e.g. once lots.json is seeded, close the LTCG gap). When a gap is closed, record `closed`, `resolution`, and — if it was closed by an audit sweep rather than by the run that found it — `closed_by` (e.g. `"auto-audit 2026-08-07"`), so the registry distinguishes "fixed in flight" from "swept up later". **Whenever you add OR close a gap this run, run `python3 scripts/gen_decisions_md.py --base-dir .` before ending** (added 2026-09-07, closes a real drift found live — nothing in this flow called it, and DECISIONS.md sat 4 gaps stale, missing the exact incidents SKILL.md's own prose cites by ID). One cheap call, no reason to batch it or defer it.
- PREFERENCES — when user gives feedback in conversation, write to state.json's preferences block; acknowledge once; read at SYNTHESIZE; affects presentation only, never analysis.
- CACHE HYGIENE — drop data_cache entries for any symbol absent >30 days (track date-of-last-seen per symbol). Ledger and journal-archive keep full history.
- last_run_dir — set to this run's `runs/<ts>/` path (enables 0.5 refresher and prior-self reads). **Never hand-write `ts` or `latest_run_dir`:** after every other state.json write in this section, run `commit-state --run-dir runs/<ts>` once more — it is idempotent and re-stamps both from the script clock (a hand-typed `ts` landed in the future on 2026-09-14).
- Keep only 10 most recent runs/; delete older ones (compute_*.json files included).
- GIT SNAPSHOT — the state directory is a git repo (initialized 2026-07-18): after all writes, `git add -A && git commit -m "run <ts> <mode>"` (quiet, best-effort — a git failure is a one-line data_quality note, never a run failure). This is the rollback path for any state corruption; it supersedes nothing (the .bak scheme stays).
- **COMPACT (added 2026-08-16, deep runs).** After all writes succeed, run
  `python3 scripts/smith_math.py compact --base-dir . --holdings runs/<ts>/holdings.json --today <date> --write`.
  It archives closed gaps beyond the 8 most recent, thesis/sector_map for names no longer held, and terminal
  proposals past the 90d scoring window — **archive, never delete**, idempotent, and every evicted record stays
  queryable via `smith_math.py gaps`. First run freed 97KB (46% of state.json), which matters because state.json
  is read every run and sliced into every prompt. Run it AFTER persist, never before: compacting first would
  evict records this run still needs.
- Release the run lock: `python3 scripts/smith_math.py lock release --run-id <run_id>` (on every path, failures included; `abort` does it for you).
Emit compact fenced MILESTONE JSON (≤15 lines: agent, mode, ts, usdinr, us{...}, sentiment{score,band}, news_watermark, risk_off_status, proposals count, data_quality).
