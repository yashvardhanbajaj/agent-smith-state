# Principles — full text

> Moved verbatim out of SKILL.md on 2026-09-14 (core cut to <=60KB). Load this file only when the core step that cites it runs. Where this text and the core disagree, the core wins — it reflects the scripted flow (`preflight`, `smith_fetch.py`, `dispatch-plan`, `postflight`).

COMPUTE-FIRST PRINCIPLE: any deterministic arithmetic (currency conversion, weights, concentration, drawdown, journal scoring, drift-vs-policy, the sentiment composite) is done by `scripts/smith_math.py` via Bash, never by an LLM sub-agent. Sub-agents exist for judgment and external data gathering (news, thesis calls, entry setups) — feed them the script's numbers, don't ask them to recompute what the script already produced. HARD GUARDRAIL: a sub-agent must never estimate or interpolate a number the script or a tool didn't hand it directly — if a figure this principle covers is missing from the embedded slices, the agent emits `null` for it and adds a one-line data_quality flag, not a best guess. This does NOT apply to the small per-symbol math specific agents own by design (smith-signals' `pos`, but ONLY while `data_cache.wk52` does not exist) — those are judgment-layer calculations the script deliberately doesn't own, not violations of this principle. **`relative_strength_1m` was removed from this carve-out on 2026-09-06 — it is now computed by `smith_math.py buckets`; see step 2.4 below for why the carve-out was wrong.** **The cluster ladder splits the same way (2026-09-08): `smith_math.py ladder` owns intra-cluster relative strength (`rel_intra_pp` — each member against its OWN cluster's equal-weighted mean return, NOT against SMH), dispersion, the redundancy CANDIDATE screen, cluster room and the dispatch gate; `smith-cluster` owns the ranking rationale, the margin-pool read, the cluster thesis, the bench and the same-bet verdicts. A cluster agent that re-derives `rel_intra_pp` is buying arithmetic at LLM prices; a script that asserts two names are "the same bet" is faking a correlation it has no return series to compute.**

EVIDENCE PRINCIPLE (the qualitative counterpart to COMPUTE-FIRST above). COMPUTE-FIRST hardens *numbers*, which travel a source-of-truth spine with a check at every joint (SANITY GATE, PERSIST GATE, STALENESS GATE, TICKER INTEGRITY, live-quote arbitration). A qualitative claim (news, a thesis call) has no equivalent spine by default — it can pass a single JSON-parser check and become a sized dollar proposal. Four standing rules close that gap (full incident histories, all verified still-accurate against SKILL.md's telling: DECISIONS.md#G58, #G44, #G59, #G72):
1. **BOTH SIDES SURVIVE COMPRESSION (G58).** Any verdict that changes a status or feeds a proposal carries `evidence_for` AND `evidence_against` as separate arrays, never a single prose clause. An empty side is an explicit `[]` plus a note, never an omitted key. Every hop compresses; a subordinate clause ("beat, but only despite a miss elsewhere") is what gets lost first, and it is not a bullish- or bearish-biased loss — it drops whichever side a schema didn't force through.
2. **VERDICT WORDS CARRY OBLIGATIONS.** "beat"/"miss" mean reported actuals vs consensus; a forward guide below the Street is `guide_below_consensus`. Reported quarter and forward guide are separate signals — name which one was weighted. "collapse"/"broken"/"deteriorating" require a magnitude and a source, per smith-catalyst's standing rule that a threat without a scale is fear, not analysis.
3. **VERIFY WHAT DRIVES MONEY, LABEL THE REST (G44, G59).** A claim gets a primary-source check only when it changes a thesis status, classifies a new position, or is cited in a sized proposal — roughly 1-3 names per run. Everything else is tagged `verified: "unverified"`, which is a normal state and never a reason to drop a claim (same degradation contract as the stops engine: unverified ≠ dropped). **PRIMARY SOURCE = `python3 scripts/smith_edgar.py --base-dir .`.** SEC EDGAR's XBRL API returns AS-FILED values for any us-gaap tag with the form, fiscal period, filing date and accession number attached — a stronger primary-source check than a filing index, arriving as data rather than prose. `verify --ticker AMZN --concepts ocf,capex,lt_debt` is the whole interface; `tags --ticker X --match debt` answers "what does this issuer actually call it"; `filings --ticker X --form 10-Q` gives document URLs. Use it BEFORE settling for `verified: "unverified"`. **Always pass `--base-dir`** — it caches the ticker→CIK map (180d TTL) and per-ticker-concept as-filed rows (3d TTL) to `edgar_cache.json`; omitting it defaults to cwd and silently drops the cache. `stockanalysis.com` **works** and is allow-listed; FMP `statements`/`earningsTranscript` remain plan-tier-denied — that is a vendor limit, not a statement about SEC EDGAR's own reachability, which is open to a declared User-Agent. When a source is recorded as blocked, record WHAT was tried and WHY, so a later run can tell a plan-tier limit from a fixable request problem.
4. **SILENCE IS NOT EVIDENCE OF ABSENCE (G72).** `state.thesis` and `state.signal_history` are both seeded from CURRENT holdings, so a fully-exited name is silent in both by construction — checking them can only ever say "never held", whatever the truth was. **Never answer "did I hold X / have I traded X" from `state.*`.** Run `python3 scripts/smith_math.py history --ticker X` (comma-separated list accepted); it reads trades.json — the only file that records positions which no longer exist — and returns trade count, first/last dates, peak quantity, and whether the name is live. Before citing an absence as fact, confirm the source checked is one where a present item *would* have appeared.


## Gap precedent search (`gaps --query`)

**`--query` is ranked precedent search, not exact lookup (rewritten 2026-09-07).** It was a single literal-substring match against each gap's JSON blob — a query had to appear verbatim in the record to hit at all, so "measurement basis mismatch" would miss a gap phrased "two different measurement bases were plotted as one line" even though that IS the precedent. It's now hand-rolled BM25 over `description + resolution + owner` (no pip dependency — every module in this compute layer is stdlib-only by design, and the corpus is ~84 records, far too small to need an embeddings/vector-DB approach) ranked by relevance, returning `--top` hits (default 8) each carrying a `relevance` score. Still lexical, not semantic: a hit requires SOME shared vocabulary with the query, not the same meaning in different words entirely. Use it — from any Wave-1/Wave-2 agent, not just the orchestrator — before writing a thesis status change, a `catalyst_threat`/`thesis_break` classification, or any verdict that feels like it might have happened before: `gaps --query "<2-4 word situation summary>"` and cite a relevant hit's ID instead of re-deriving reasoning this desk has already logged. A hit is a candidate precedent, same evidentiary tier as any other unverified claim under the EVIDENCE PRINCIPLE — weigh it, don't auto-apply it.
