### 3.5. THE DESK LOOP — analysts talk to each other until nothing is owed (added 2026-09-19)
**User instruction:** the sub-agents must not just compute side by side — they ask, tell, answer and argue, and proper analysis outranks time and tokens. The run is **not limited to two waves**: add as many layers as the conversation needs. Protocol and router: `scripts/smith_comms.py` (module docstring has the why).

Every slice now carries `desk_protocol`, `desk_directory` (who owns what, who is on the desk), `desk_inbox` and `desk_replies`. Agents put `asks` / `tells` / `answers` in a `comms` block of their JSON tail.

**Loop** — after each layer lands (Wave 1 merged; Wave 2 merged + crosscheck; the strategist merged):
1. `python3 scripts/smith_math.py comms-route --base-dir . --run-dir runs/<run_id> --today <date>` — harvests every tail, opens debates from crosscheck, applies revisions, returns `deliveries` and a literal `next` list. Save nothing by hand; the ledger is `runs/<run_id>/comms/messages.json`.
2. Do what `next` says, in order:
   - `remerge` non-empty → `merge-tails … --agents <remerge> --revision`, then re-run `crosscheck`. (`--revision` skips the once-per-run side effects: `stress_table_prev`, ladder track-record, learning observation.)
   - `new_agents` → render `slices … --agents <keys>` and dispatch each in **answer-only mode** ("answer your desk_inbox; your reply file is X") — this is a new layer, on demand.
   - each `resume` delivery → **SendMessage to that agent's id if it is still live** (it keeps its full context), otherwise a fresh dispatch with its slice. Message: "DESK ROUND <n>: read `<inbox>`, answer every message per desk_protocol, write your reply tail to `<reply_file>` and return the same JSON." Write the returned tail verbatim to `reply_file` if the agent did not.
   - `desk_requests` → answer from scripts (never from judgment), writing `runs/<run_id>/out_desk.r<n>.json` = `{"comms":{"answers":[{"id","position":"held","answer","evidence"}]}}`.
   - resume/dispatch agents of one round **in parallel**.
3. Run `comms-route` again. **Repeat until `converged: true`.** A round cap (6) exists only as a runaway guard; hitting it expires what is left, and every expired or unanswered message is reported — never answered by you on an agent's behalf.
4. `queued_for_scheduled_agents` are waiting in the slices of agents whose layer has not run yet (e.g. the strategist). They do not block convergence; they are harvested from that agent's normal tail on the next route.

**Stage 2 joins the loop.** Dispatch the strategist only after the pre-strategist loop has converged (its slice then carries `comms_digest`: settled debates, revisions, unresolved items). After merging it, route again: if it asked something blocking, the owner is resumed, the answer comes back, the strategist is resumed to finalise — its proposals are final only when the loop converges again. Then `commit-state`.

**Cost is accepted by design.** Each resume is a real agent turn (roughly 15–40K tokens). Do not trim rounds to save tokens; do not skip a delivery because the answer "seems obvious". The only legitimate early stop is `converged: true`.

`python3 scripts/smith_math.py comms-status --run-dir runs/<run_id> [--full]` prints the digest at any point.

## HARD RULES
- **CONTEXT HYGIENE (added 2026-09-14, closes a real token-waste incident).** On 2026-09-09 a single `Artifact action:"read"` call to sanity-check the live dashboard dumped its full ~480KB embedded JSON payload into the orchestrator's own context — 120K+ tokens for one lookup, on what was meant to be a "quick" run. **Never pull a large file's full content into the conversation just to inspect it.** Concretely: (a) to check the live dashboard for pending decisions, follow §1.7's path (`Artifact action:"read_db"` against the `decisions` collection → run-dir file → `sync-decisions`) — never `Artifact action:"read"` on the page itself, which is guaranteed to return the whole ~600KB document for an owned artifact; (b) when inspecting any `compute_*.json`, `holdings.json`, or agent-tail file via Bash, pipe through `python3 -c` and print only the specific field/count you need, never `cat`/`head` a multi-KB JSON file wholesale into a tool result; (c) large tool outputs (a `networth_holdings` pull, a multi-symbol price fetch) are working data for the next script call, not something to re-print for your own review once you've saved it to a file. The orchestrator's own context is a cost center exactly like a sub-agent's — it just never shows up in `usage-report` because nothing meters it.
- INDmoney ONLY for holdings; headline value/P&L = networth_snapshot's US_STOCK entry (matches the app).
- EVERYTHING in USD (derived rate stated once). Per-share prices, 52-week levels, analyst targets are native USD.
- COMPUTE-FIRST: deterministic math goes through `scripts/smith_math.py`, never through an LLM sub-agent re-deriving numbers the script already has (see PRINCIPLES).
- **RETENTION IS A POLICY, NOT A PER-FILE AFTERTHOUGHT** (full story: DECISIONS.md, search "state.json had reached"). A declarative `RETENTION` table (smith_memory.py) drives `python3 scripts/smith_math.py compact --holdings runs/<ts>/holdings.json` (dry run by default, `--write` to apply, idempotent) — archives closed gaps beyond the 8 most recent, thesis/sector_map entries for names no longer held, and terminal proposals past the 90-day scoring window. Invariants: **archive, never delete**; never evict something still live; archive stays **queryable** via `smith_math.py gaps --id G44 | --query <text> [--top N, default 8] | --open-only` (searches both the live and archived registries). `postflight --phase close` runs it with `--write` on deep reviews.

- **ONE FIELD, ONE READER** (full story: DECISIONS.md#G58, #G60). When a stored field can hold two shapes, fix it with a single shared reader — never another `isinstance` branch at the call site. Thesis status/text/evidence: `smith_risk.thesis_status/thesis_text/thesis_evidence` (whitelists against `KNOWN_STATUSES`, returns `None` rather than inventing a value). Mixed per-ticker namespaces (a dict sharing data rows with bookkeeping keys like `schema_version`/`_note`): iterate via `smith_risk.data_entries()`, never a hand-rolled filter. Gap status: `smith_risk.gap_status`/`gap_is_live` (whitelists against `KNOWN_GAP_STATUSES`, unreadable counts as **live** — safe default when unsure). `smith_math.py validate` fails on any of these regressing to a legacy shape. Run `validate` before trusting a run whose state was hand-edited.
- **A QUARANTINE SCHEMA CARRIES THE FULL PAYLOAD, NEVER JUST A POINTER** (full story: DECISIONS.md#G69). When work fans out to parallel agents with a shape for rows they *couldn't* resolve, that shape must include every field already extracted (for ledger work: `qty`, `price`, `amount`, `order_type`, `ts_utc`, plus whatever blocked it) — never just `{ticker, ts_utc, missing}`. A schema for unresolved items defines what survives failure: preserve the expensive part (extracted data), discard only the cheap part (the resolution). A complete quarantine row is recoverable later on its own; a pointer row means re-doing all the work.
- TICKER INTEGRITY: never infer a ticker symbol from a holding's display name. Resolve once, cache in data_cache.ticker_map, flag new resolutions in the briefing for the user to verify.
- **SMITH-REBOUND TRIGGER:** dispatch on `compute_triggers.json`'s `correction_state` = `pullback`/`correction`/`deep_correction` (`dispatch-plan` applies it) — never on the pre-market gate, stop-outs or spare cash. **Widened to include `pullback` 2026-09-15**: rebound_candidates exists specifically for a pullback, so gating on `correction`/`deep_correction` only meant the screen never refreshed while the book sat in pullback territory — it went dark 15 days straight through several pullback-tier sweeps before this was caught. A calm gate during a real correction (or pullback) is the most constructive combination to report.
- NEVER place trades or move money. Strategist proposals (including rebound candidates) are suggestions for the user's review — sized for clarity, not instructions. Non-advice caveat every run, in character, never dropped.
- Corporate actions (splits, bonuses) are never counted as flows — the script's qty_changes already flags likely_corporate_action; verify before treating any qty change as new money.
- State files are the memory of record; write only inside `/Users/yb/Claude/AgentSmith/`. Never modify a confirmed policy.json without explicit user instruction.
- If a sub-agent fails: retry once via SendMessage, then degrade that section and name it in data_quality. If a script stage fails: leave its section `null` and name it — never have an agent compute it inline. Every path ends by releasing the lock (`postflight --phase close`, `lock release`, or `abort`).
- PERSIST GATE: when `compute_book.json` reports `persist_safe: false` (G3 and the sanity gate), `commit-state` withholds the price-derived keys and `postflight` appends no ledger row. Never work around it by hand.
- STALENESS GATE: any user-facing output containing actionable price levels (stops, entries, sized $ proposals) states its price source and timestamp. If snapshot and live prices diverge >3% on a name (G3), the live quote (`live_quotes.json`, pre/post-market aware) wins for that output and the divergence is stated plainly.
